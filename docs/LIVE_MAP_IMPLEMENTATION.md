## Actual repository and implementation

Next.js 16.4.2/React 19 modular application, existing PostgreSQL/Supabase backend, Socket.io server, Docker backend, K3s renderers, Capacitor web-runtime clients. No native MapLibre bridge, UE project/toolchain or live jobs application backend is present. Stay APIs intentionally return preview/demo and fail closed for public commercial mutations. Those boundaries are preserved.

Implemented MapLibre GL JS 6.16.0 (BSD-3-Clause, exact lockfile). The shared `components/location/LiveMap.jsx` lazily imports the renderer and includes clustered approximate public points, optional price labels when provider glyphs exist, camera controls, explicit GPS, manual place search, map/list switching, details/deep links, favorites, route preview and controls for supported building extrusion. Public point-only maps replace automatic Google iframe loading; external Apple/Google navigation remains an explicit link. A provider can lack building layers or glyphs; no height or label coverage is invented. Current dark mode changes interface surfaces, not a promised provider-specific dark basemap. Selected-item preview supports a pointer/keyboard expansion handle; native touch gesture acceptance remains NOT_TESTED. Polygon-drawing UI is NOT_IMPLEMENTED.

The pinned worker is served as `public/maps/maplibre-worker-6.16.0.mjs` with the upstream license, avoiding bundler-relative worker failures. A unit test verifies byte identity against the pinned installed package. Only this unmodified vendor worker is excluded from app-source lint. No CSP relaxation is used. Constructor-time maxBounds was removed after real browser testing exposed a MapLibre 6 matrix initialization failure; application bounds remain validated server-side.

Publishing adds an optional map point selector to the existing address form; exact selection remains in existing private listing fields. The visible preview is a stable 0.01-degree cell center, with a conservative 1,600m area label, not a precise house or handover point. Missing coordinates never become invented geocodes. Reviewed migration initializes only the new derived projection from existing eligible assets; it never updates source assets or geocodes missing addresses. Radius distance uses WGS84 great-circle calculations; PostGIS uses geography for radius/GiST indexes. Polygon query input is bounded and validated; no arbitrary SQL/RPC privileges reach browsers.

## Database and event contract

Migration: `supabase/migrations/20261107140000_live_map.sql`. Rollback: `deploy/vietnam/live-map-rollback.sql`. PostGIS installed only within an isolated, temporary QA database during validation. Trigger projects eligible public assets, excluding locked, disputed, sold and neighborhood-only entries; only ward/province label and approximate geometry are retained. Existing precise address/coords are never part of map RPC results. The transaction-scoped advisory lock serializes map sequence allocation with commits to prevent a lower sequence committing behind a subscription watermark. Throughput impact needs load measurement.

All new public-schema tables, sequences and RPCs revoke PUBLIC/anon/authenticated permissions. Only service_role receives the required backend operations. Apply `deploy/vietnam/security-lockdown.sql` after reviewed deployment migrations. RLS stays enabled. Reuse existing transactional business state; map projection/outbox is derived, not inventory/payment authority.

`GET /api/maps/search`: bounded bbox (maximum 5° each axis), domain, transaction, category, q, min/max, optional radius/origin, optional closed polygon, limit 1–200 and offset capped at 2,000. Query response is public GeoJSON plus cursor/paging. Bbox/radius/polygon are PostGIS queries, not client filtering over a complete private catalog. Nonlive domains return explicit DOMAIN_NOT_LIVE and empty data. API clients must distinguish missing/stale/provider-unavailable from empty business inventory.

When opened from Explore, the map preserves the first at most 200 currently loaded filtered listing IDs, including the existing page's province/group/date/saved filters, and revalidates them through the backend spatial projection. This bound is explicit rather than claiming a complete unpaginated global catalog. Unrelated URL radius units are not forwarded as raw coordinate/radius requests. Product deep links preserve rental dates/times or sale intent. Full cross-domain/date-aware spatial inventory queries remain acceptance work, not inferred from this loaded-result bridge.

Socket `/maps`, schemaVersion 1: client sends `map:subscribe {query,cursor,ids}` from its snapshot; server emits `map:delta {cursor,events:[{op,id,version,feature?}]}`. Versions are decimal strings to avoid JS integer truncation. Removal IDs are sent only for markers already known to that subscriber. Public deltas carry only approximate GeoJSON. Replays/tombstones cannot resurrect older versions. A process shares a single outbox poll across subscriptions; origin, subscription rate, payload, client count, known-ID count, lag and writable transport are bounded. Socket.io supplies heartbeat/reconnect; reconnect or overflow refetches the viewport. Redis fanout is not installed: all renderer processes can poll the durable backend outbox independently. Initial 200-client/process admission is a safety bound, not proof of 200 concurrent performance. User-visible price/availability remain subject to original server revalidation.

UE consumers, when later available, may consume this public WGS84 GeoJSON and event contract; convert geodetic coordinates in the client, retain CRS/accuracy/version and use server entitlement-specific APIs for private routes. No UE rendering/synchronization was implemented or claimed.

## Providers, configuration and privacy

No public OSM raster tiles, public Nominatim, public OSRM demo or MapLibre demo tiles are configured as production infrastructure. Rendering is unavailable until reviewed provider configuration exists. No paid service/account/key activated. Server environment template: `deploy/maps/env.example`. Resource URLs must be HTTPS and explicitly allowlisted; DNS/public-IP pinning and bounded redirect/body/time reuse the existing hardened downloader. Styles rewrite tile/TileJSON/glyph/sprite destinations through same-origin endpoints; secrets are injected server-side only. OSM and configured provider attribution are retained. Provider license terms determine caching/derivative use and must be reviewed. Current resource responses use private browser caching (5 minutes); confirm provider contract permits that before activation.

Geocoder adapter expects GeoJSON forward/autocomplete responses; debounce and per-IP request limits apply. Reverse requests use a separately configured `RELOO_MAP_REVERSE_URL` and explicit `reverse:true,coords`; no background reverse lookup is triggered. UI address normalization/automatic correction is not implemented and must not overwrite manual address input. Routing expects an OSRM-compatible response at configured driving/walking profile URLs. No public demo routing service is silently used. ETA is provider estimate without live traffic, and public destination is approximate. User origin is acquired only after explicit GPS click and submitted only after a separate route action; no watchPosition, background tracking or location history database is added. Production logs must retain route templates rather than raw query/location payloads. Process-local quotas do not replace provider project quotas across all renderers.

New processing: public approximate map projection, short-lived geocoder response and route request, operational version/id outbox. No photo/identity/contact fields or private GPS events. Rules: RULE-005/006/007/008/009/010/012/014/015/016/017/018/020, RELOO-RENTAL/STAYS/JOBS/WORLD. Provider rights, retention schedule and legal applicability: NEEDS_LEGAL_REVIEW; no binding policies auto-edited and no approval invented. No raster asset imported. Existing asset/field inventories remain accountable review items, not mechanically approvable lists.

## Verification and performance

Reproducible commands: `node --test tests/live-map.test.mjs tests/live-map-realtime.test.mjs tests/location-map.test.mjs tests/public-listing-privacy.test.mjs tests/security-hardening.test.mjs`; `node scripts/live-map-db-check.mjs` (requires existing private SSH key and authorized isolated QA database access); Playwright CLI `run-code --filename=scripts/live-map-browser-check.js` against local port 4537.

PostGIS QA tested real PostgreSQL/PostGIS in a fresh synthetic database, verified migration/search/privacy/visibility/price/events/backend-only privileges, then rollback and deletion of only the created QA database. No production migration, asset mutation or restart. JS tests verify query bounds, radius, polygon, exact/approximate separation, host policy, styles, version replay, privacy projection and actual WebSocket origin/delta/removal behavior.

Targets remain unachieved/not measured: licensed tile warm start <=1.5s, full HTTP spatial API p95<=300ms, realtime p95<=2s, device 60FPS, 100/500/2000 concurrent users. The 2s outbox poll interval alone does not prove a 2s end-to-end p95. Do not run high-concurrency load against the active production host merely to obtain numbers. Fixture style rendering measures only local UI, not OSM coverage or production provider latency. API/fps/memory/provider-cost telemetry and incident alert dashboards are PARTIAL/NOT_IMPLEMENTED.

Measured QA: 1,000 synthetic projection rows, 100 sequential PostGIS function calls in the isolated QA database on the existing PostgreSQL server: SQL-only p95 **3.753ms**, mean **3.499ms**. This excludes HTTP, authentication, network, provider calls and concurrent load; it is not the <=300ms API p95 acceptance result. The first background-only MapLibre browser measurement was 2,295ms including local dev/import (no tiles/network emulation); it does not meet or establish a warm-start production target. Browser fixtures verified no background GPS, explicit denied-GPS fallback, autocomplete, manual choice, offline notice, responsive widths, list/map and UI dark controls. Original shader/worker failures were fixed; final browser artifacts retain actual results rather than treating the initial failures as PASS.

Dependency remediation: compatible `follow-redirects` update removed the observed HIGH advisory. No forced Next/eslint downgrade was performed. Remaining MODERATE findings in root/mobile are tracked by audit artifacts; tooling audit was clean at this check. These are current technical snapshots, not permanent safety guarantees.

## Release readiness and rollback

Overall BLOCKED: provider not configured/reviewed; existing product domains have real backend dependencies; live inventory/backfill/device/load acceptance outstanding; Guardian manual legal/asset/domain approvals and inventories remain incomplete. Technical code can be checked/fixed autonomously, but no human approval can be fabricated to force PASS.

Full regression initially found old staging fixtures outside their 31 October review window and new unreviewed assets not handled by the legal-dossier test. Fixture clocks are now explicit, while expired/malformed real review windows remain blocked. The UAT configuration generator validates against its passed fixture time and does not extend a production review expiry. New asset records remain NEEDS_PROVENANCE_REVIEW without an invented owner attestation. Realtime fixture initially advanced its mock watermark before publishing the corresponding event; full-suite scheduling exposed the resulting missing-event race. The fixture now advances committed watermark and events together, matching the database contract. These are test/runtime fixes, not legal/risk waivers.

Before release: satisfy current source-bound Guardian checks, isolate staging, approve provider contract/attribution/retention, provision tiles/geocoder/router and quotas, apply/test migration + lockdown and reviewed backfill, validate domain ACL/privacy and actual data, measure load off production, synchronize Docker backend/all K3s renderers and verify desktop/iPhone/Android against one build/catalog. Native config is unchanged. No production deployment under this implementation step.

Rollback restores matching prior web/backend artifacts; remove projection/outbox/trigger only via reviewed rollback, preserve source assets/private addresses and PostGIS extension. Incident: disable map config or remove provider approval to force list/manual fallback, retain business flows, inspect bounded errors/admin readiness, rotate compromised keys through the existing secret process. Do not disable production Auth/database or weaken CSP.
