# Final identity review and server-bound automatic expiry

Owner requests production implementation: front/back capture and QR, then existing portrait/liveness capture, then one concise final review. Automatic expiry comes from the printed front expiry on CCCD and back expiry on the newer identification card. Customer does not type an expiry. No guessed date or success before committed backend approval. Missing/ambiguous/expired reads route to retake or existing staff review. Existing face capture is not promoted into a biometric/government authenticity claim by OCR.

Change assessment: private KYC OCR image service, final review/consent UI, server-bound preview receipt, submission validation, additive notice/version SQL and existing notification mechanism. Rules005–010,013,016–020 apply. Existing identity fields only; no marketing purpose, chatbot knowledge, third-party OCR transfer or new persistent raw-text store. Current business controller/readiness and access checks remain mandatory. Owner-provided samples are authorized solely for private OCR testing; temporary server copies are RAM-only under a root-private directory, mounted read-only to a no-network bounded test container and removed after testing. Retain only anonymous pass/fail/timing records; do not store document content or real identifiers in repository/output reports.

Expiry preview is independently read from original image captures, never from QR/client input. Authenticated encrypted short-lived receipt binds purpose, profile, camera session, original front/back hashes, QR hash, notice/controller version and extracted expiry. Final submission verifies it server-side and ignores/rejects a different client expiry. No new expiry source is trusted merely because it was displayed. Receipt expires and cannot cross account/capture/controller versions. Existing camera session consumption prevents duplicate submission. An unavailable date never becomes a fabricated date or a successful verification.

Notice wording is short under the explicit checkbox, with a link to current processing details. Updated capture/processing notice version records this OCR purpose; no legal entity/approval is invented. Pre-capture notice still precedes processing. The final checkbox confirms the displayed information and records current processing acknowledgement without marketing consent. State success follows APPROVED only; REVIEW receives a pending message. Existing backend notifications must be idempotent and based on committed state transitions.

Production activation requires source-bound checks, model/image dependency review, restored-database migration trial, encrypted backups and synchronized shared runtime. Existing source0907d825 release exception is not a new legal/model license approval. Any remaining unverified model rights/manual review must be disclosed in the concrete release decision, not silently marked PASS. Physical-device and face matching coverage must reflect actual tests.

The final mode uses a dedicated OCR-only private service, with no face/liveness routes and no public port; it shares the existing authenticated image parser and OCR implementation. It runs on an internal Docker network with3GB/2CPU limits, read-only filesystem/model mount and dropped capabilities. The previous face/liveness service is not replaced or rebuilt. Set KYC_OCR_SERVICE_URL to the private OCR service and RELOO_KYC_AUTO_EXPIRY=1 on the shared app runtime. No real sample card is stored in the code/test fixture suite.

Reports contain case labels/booleans/timings only. All four temporary RAM images were removed; local originals unchanged. No real person was enrolled, no production KYC row/notification was created by sample testing, and no external face matching or document API was called.
