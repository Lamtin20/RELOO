VietOCR recognizes text-line images; it is not a full identity-document detector, forgery detector or government verification API. Existing Tesseract geometry supplies bounded line regions. A CPU-only VietOCR adapter reads those regions independently, with no QR values supplied to inference. Tesseract and VietOCR candidate discrepancies remain visible; QR never corrects OCR text before comparison. Provider scores are not calibrated identity confidence.

Model loading is opt-in, pinned to local read-only weights with a required SHA256, and uses torch.load(weights_only=True), strict state dictionaries and pretrained=False. No runtime model/config download, torch hub backbone fetch or external document API. Request concurrency remains one per KYC worker; bounded lines, output lengths, threads and per-document deadline. Unavailable/invalid models do not return fabricated extraction or downgrade to a successful VietOCR status.

Transient comparison uses the user's existing original front/back captures only after authenticated ownership, current controller/notice readiness, explicit separate OCR choice and matching capture hashes. Images and extracted candidates are not written to disk, logs, analytics, the chatbot corpus or a new database. Return only number, name, date-of-birth and expiry candidates needed for comparison, not raw OCR text or unrelated card attributes. Results exist in request memory/UI until cleared; withdrawal/unmount aborts the request and clears the result. Existing final evidence retention is unchanged. This technical design does not amend binding legal policies or establish a legal basis by itself.

Current KYC QR-only preview/submission must still work when OCR is off or fails. The optional comparison cannot approve/reject a submission, set account verification level, auto-fill declared expiry or override QR/accepted fields. The UI states that reading text does not establish document authenticity. Missing/ambiguous fields require review/retake; disagreement is not an accusation of fraud.

Validation requires synthetic data only: parser fields, diacritics, mismatches, ambiguous numbers, missing labels, model missing/checksum failure, no-network model initialization, owner/consent/hash/origin gates, no persistence and existing QR approval regression. A real local model smoke test is separate from fixtures and does not establish accuracy on real CCCD/cards. Production activation requires current release evidence and model-rights/quality review; no prior source-bound release exception is silently reused.

## Running and deployment

`npm run test:vietocr` exercises pure extraction, comparison, guarded endpoint and the existing approval boundary. Python tests need Pillow; the real runtime additionally needs the existing CPU torch2.8/torchvision0.23 and pinned optional inference package. The Guardian CI definition adds the lightweight offline Python fixture suite; the remote workflow itself has not been run here. A complete Python dependency/image vulnerability audit remains NOT_TESTED and is required before activating a new production KYC image.

Provision a local model with `python scripts/provision-vietocr-model.py /srv/reloo/data/vietocr`. The pinned SHA256 in tools/vietocr-toolchain.json is an observed artifact hash, not a signature or license approval. Run Compose with existing production/security overlays plus deploy/kyc/compose.vietocr.yml only after the release decision; it enables the optional build dependency and read-only model mount. Set app flag RELOO_KYC_OCR_COMPARISON=1 only after model readiness, rights review and actual capture-quality evaluation. Missing flags keep the old QR workflow and hide the optional comparison panel. Do not replace production KYC/face or shared web runtime with the research image.
