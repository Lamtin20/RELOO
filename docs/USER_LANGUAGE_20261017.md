# Account display language

Settings live at `/dashboard/profile/language`, linked from the personal profile, account page and the existing Calendar & preferences tool group. The page offers Vietnamese and English with real inline SVG Vietnam/US flags, radio labels and an explicit Save action. No page-level display-language select remains in Neighborhood, Neighborhood admin or Rental Care.

First use selects the first supported device/browser language (vi variants → vi-VN, en variants → en-US; unsupported-only preferences fall back to Vietnamese). SSR uses weighted Accept-Language and a validated essential UI cookie. After authentication, the profile's saved preference is authoritative; legacy `?lang=` links cannot override it. The first authenticated initialization is persisted once with a row lock. Subsequent device initialization cannot overwrite an explicit saved choice. Each account has its own cached fallback; logout/account switch does not reuse another account's record. Focus refresh fetches the server choice. HTML lang follows the effective language.

The LocaleProvider wraps the existing application; translated Neighborhood, calendars, residence settings, Control Center, loading and common navigation consume it. The existing dictionaries are reused. Common navigation/cookie UI translations were added. This is not automatic translation of user listings or authored articles. Legacy screens with hard-coded strings can still fall back to Vietnamese; new UI must use LocaleProvider and a bilingual dictionary rather than a local language state or query selector.

`ui-language.sql` is additive: nullable profiles.ui_locale and backend-only `reloo_ui_language_set`. The authenticated API derives the profile ID from HttpOnly auth, validates the two locale values, checks origin/rate and never accepts an actor ID. The RPC atomically updates UI language and the existing optional NK/Rental Care notification locale, preserving destination, onboarding state, marketing choice and other consent. Initializing language never enables Calendar or marketing. No public data/RPC grant is added; security-lockdown runs after migration. Rollback restores app/source and retains the additive preference column, avoiding destructive data restoration.
